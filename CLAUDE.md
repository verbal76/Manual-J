# Rules for Claude sessions in this repo
- Public naming: the product is **Manual J**; the only public version is `v<number>` (sequential integers). Artifacts `Manual-J-v<N>.apk`, GitHub Release title `Manual J v<N>`, marked Latest. Never use codenames, build numbers, SHAs or semver in titles/filenames. Full rules: `docs/RELEASING.md`. Next delivered build is the number in `release/VERSION`.
- Never reuse a version number; never replace a release's binary.
- Engineering rules: no invented engineering constants; unsourced values stay UNKNOWN; do not claim ACCA approval; calculation engine stays UI-free and deterministic; ANALYTIC-001 must stay 3,795 / 1,347.2 / 415.029 Btu/h.
- Package ID is com.hotatticgames.manualj (decided; do not revert). OTA hosting is intentionally undecided; do not publish OTAs or make the repo public.
- Verify claims against the built APK, not just source (permissions were once misreported from source).
- **Studio splash is a standing requirement:** the app must open with the Hot Attic Games card before its own UI, using the canonical file `Hot_Attic_Games_Master_Logo_ALPHA_FINAL.png` (repo root; transparent PNG; never redraw, crop, stretch, recolor or replace; the old `branding/Hot_Attic_Games_Master_Logo.png` name is obsolete; do not wait for another asset). Cold launch only (never on resume), ~2.6 s with fades, contain-fit, silent. Implementation: `index.html` + `src/ui/splash.ts`; guarded by `tests/splash.test.ts`. Details: `docs/RELEASE_IDENTITY_UI.md`.
- **GitHub Actions budget is scarce (standing owner policy):** Actions minutes are shared across the owner's projects with a small monthly budget. Before starting any workflow ask: "Does this need GitHub Actions, or can I prove it locally?" Validate locally first (tsc, vitest, validate, build, Playwright e2e). `android.yml` is manual-only: no APK/AAB/EXE builds on routine pushes; docs-only changes use zero minutes; never re-run or rebuild the same SHA when a verified artifact exists; no re-runs just to see if a flaky test passes. Use Actions only for: a real release candidate (push `release/vN`), a physical-test APK actually needed, OTA publication checks, store/release builds, or a platform check that can't be reproduced locally. Concurrency groups cancel superseded debug runs. Never weaken signing, OTA/runtime compatibility, APK qualification or rollback gates to save minutes. Pushing `release/vN` runs `deliver.yml` (the only automatic expensive trigger).
